# 用户旅程与待验证假设

状态：尚未完成真实目标用户访谈。以下内容是基于项目 PRD、公开兽医资料和照护者研究形成的产品假设，不应表述为已经验证的用户事实。

## 目标用户

首次长期照护糖尿病小狗，需要在日常生活中执行兽医给出的方案，并在复诊时提供清晰记录的宠物家长。

## 假设旅程

| 阶段 | 可能任务 | 可能负担 | MVP 响应 |
| --- | --- | --- | --- |
| 刚确诊 | 理解每天需要完成的事项 | 信息多、焦虑、担心做错 | 用户自行录入今日计划，产品不生成医疗方案 |
| 每日照护 | 进食、观察、测量、已执行注射 | 重复填写、容易忘记时间 | 四个快捷入口、默认当前时间、复用食物名称 |
| 日常回顾 | 确认是否已经记录 | 担心遗漏或重复 | 今日时间线、任务关联状态 |
| 复诊准备 | 整理多日记录和备注 | 信息分散、重新抄写 | 区间报告和原始数据表 |

## 需要验证的问题

1. 用户是否更需要“今日计划”，还是只需要高速记录入口？
2. 进食和已执行注射放在同一表单是否符合真实顺序？
3. 用户更常使用精确食物/饮水数值，还是相对平时的观察？
4. 四类快捷入口是否覆盖至少 80% 的日常记录？
5. 兽医在复诊时真正需要哪些字段和时间粒度？
6. 用户是否理解任务状态“尚未在本应用记录”不等于实际未执行？
7. 用户是否会把趋势图误解为医学结论？
8. JSON 备份是否足够易懂，还是需要进一步提供 CSV？

## 访谈与测试计划

- 访谈 5 名照护者，要求展示脱敏后的真实记录方式。
- 访谈或审核 2 名兽医/兽医助理，确认字段与边界文案。
- 用 5 个任务测试建档、进食与注射记录、编辑历史、查看趋势和生成报告。
- 记录完成时间、求助次数、错误、边界误解和主观负担。
