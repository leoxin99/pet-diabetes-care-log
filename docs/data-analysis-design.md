# 记录数据分析设计

版本：0.7.0-alpha.1（schema v0.5）

## 目标

帮助宠物家长判断“记录是否连续、字段是否完整、能否形成可供复诊核对的材料”，同时展示产品的数据建模、质量检查和描述性分析能力。

本模块不回答“数值是否正常”“病情是否改善”或“治疗是否需要调整”。

## 用户问题

1. 最近一段时间一共记录了多少天，是否存在大段空白？
2. 血糖、进食、已执行治疗、体重和状态观察分别记录了多少？
3. 血糖单位和场景字段是否一致、完整？
4. 数据主要集中在哪些时段，复诊前是否容易发现记录偏科？
5. 如何把当前范围导出给用户自行分析或与兽医核对？

## 数据处理链路

```text
版本化 CareRecord
  -> 按本地日期范围筛选
  -> 按记录类型、单位和时段分组
  -> 计算覆盖与字段完整性
  -> 生成描述性统计与质量检查
  -> 页面展示 / CSV 导出
```

所有派生结果在浏览器内即时计算，不写入第二份持久化状态，不上传数据。

## 指标定义

| 指标 | 定义 | 边界 |
| --- | --- | --- |
| 记录总数 | 时间范围内 `CareRecord` 数量 | 一条记录可包含多个数据类型 |
| 覆盖天数 | 至少有一条记录的本地自然日数量 | 不代表照护质量 |
| 有记录日期覆盖 | 覆盖天数 / 所选自然日数 | 只反映是否有记录，不是评分 |
| 有记录日均 | 记录总数 / 覆盖天数 | 不推荐目标频率 |
| 数据维度 | 至少出现一次的记录类型数量 | 血糖、进食、治疗、体重、状态、备注 |
| 类型分布 | 各字段在记录中出现的次数 | 同一记录可计入多个类型 |
| 时段分布 | 按记录本地小时分为 00-05、06-11、12-17、18-23 | 不解释作息或医学意义 |
| 单位一致性 | 所选范围中使用的血糖单位种类数 | 不自动换算或合并单位 |
| 字段完整性 | 场景、进食完成情况、结构化观察是否填写 | “不确定”被保留为真实输入 |
| 数值摘要 | 同一单位内的数量、最小、最大、平均记录值 | 不提供正常区间或健康判断 |

## 数据质量规则

- 同一范围存在 `mg/dL` 和 `mmol/L` 时提示“多种单位”，不自动转换。
- 血糖场景为 `unknown` 时计入待补充数量。
- 进食完成情况为 `unknown` 时保留原值并提示。
- 状态观察必须至少包含食欲、饮水、排尿、活动或症状中的一项，才计为有结构化明细。
- CSV 只导出用户已保存字段，不生成推断列。

## CSV 数据接口

导出字段：宠物 ID、记录时间、血糖值/单位/场景、进食完成情况、饮水、治疗类型/名称/实际记录量/单位、体重、四类观察、症状和备注。

文件使用 UTF-8 BOM 和稳定英文列名，方便 Excel、Python 或 SQL 工具继续处理。

## 验收标准

- 7/30/90 天切换后，概览、质量检查、图表、摘要和 CSV 使用同一批筛选记录。
- 不同血糖单位分别汇总，不发生静默转换。
- 无数据和单一数据类型均有明确状态，页面不报错。
- 375px、768px、1440px 无横向溢出。
- 页面与 CSV 不包含诊断、治疗、剂量或医学阈值建议。
- 分析纯函数有单元测试，Demo 流程有 E2E 验收。

## 后续验证

- 与真实宠物家长测试“能否发现缺失字段”和“复诊前导出是否有用”。
- 与兽医确认字段是否足以支持沟通，但不让产品替代专业判断。
- 观察用户是否理解覆盖率是记录完整性，而非健康评分。
- 后续可增加用户自定义字段和本地 SQL/SQLite 分析，但优先保持数据迁移和隐私简单。
