## 1. 项目定位

糖宠照护是面向第一次长期照护糖尿病小狗的宠物家长的 local-first Web App。它帮助用户记录已经发生的照护行为和观察事实、检查记录质量、回看趋势，并生成便于复诊沟通的材料。

产品只做记录、整理、描述性分析和沟通辅助，不诊断、不判断病情、不推荐治疗，也不提供胰岛素剂量建议。

## 3. 数据分析设计

处理链路：

```text
CareRecord
  -> 按本地日期范围筛选
  -> 按类型、单位和时段分组
  -> 计算覆盖率与字段完整性
  -> 生成描述性统计和质量检查
  -> 页面展示 / CSV 导出
```

已实现指标：

- 记录总数、覆盖天数、覆盖率和有记录日均。
- 血糖、进食、注射、体重、状态、备注六类数据维度。
- 00-05、06-11、12-17、18-23 四个记录时段。
- 血糖单位一致性、场景字段完整性、进食完成情况和结构化观察完整性。
- 血糖按单位分别汇总，体重单独汇总；不静默换算单位。
- CSV 只导出保存过的原始字段，不增加推断列。

详细定义见 `docs/data-analysis-design.md`。

## 7. 下一阶段优先级

### P0：真实需求验证

1. 招募 5 名有慢病宠物照护经验的用户完成首次建档、当日记录、查漏和导出报告任务。
2. 记录任务完成率、耗时、卡点、误解和主动提出的需求。
3. 邀请 1-2 名兽医或兽医助理审核字段、术语、复诊报告和安全文案。
4. 根据证据更新 `docs/user-research.md`，不要先假定功能方向。

### P1：分析产品优化

1. 增加缺失记录日历或时间热力图，帮助用户发现记录空白。
2. 支持用户自定义复诊时间范围和字段选择。
3. 为 CSV 增加可下载的数据字典，但继续保留原始值。
4. 评估“记录完整性提示”是否被误解为健康评分。

### P2：架构演进

1. 用户验证后再决定是否引入 IndexedDB / SQLite、云同步和家庭协作。
2. 小程序版本必须先明确数据存储、授权、隐私和通知机制。
3. AI 能力只考虑记录整理、缺失提示或基于用户自有数据的摘要；任何输出都必须可追溯并经过安全审核。
